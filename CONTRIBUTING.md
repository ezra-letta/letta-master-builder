# Contributing

Letta Master Builder is an independent, unofficial community project. Contributions do not become official Letta documentation or guarantees.

## Current contribution scope

The repository is an unpublished, local-first Phase 1 scaffold. Work should remain local and reviewable until publication is separately approved. Do not publish, create remotes, push, deploy, or make live service calls merely because a contribution is requested.

Revision 0.4 release-candidate documentation and control contracts must preserve `ASSESSMENT_REQUIRED`. Do not convert the read-only curriculum into runnable Agent Foundry software, execute learner/evaluator work, award readiness, or make Runtime Validation or Production Qualified claims without their separately approved evidence gates.

## Evidence discipline

Separate:

- official Letta product claims, supported by registered official documentation or released artifacts;
- exact package/source observations, tied to immutable versions;
- project design decisions and maintainer synthesis;
- production heuristics;
- unknown or untested behavior.

Do not present project facts as official Letta guidance. Scope behavioral claims by version, backend, topology, and observation date where relevant. Never invent evidence or claim live validation from static review.

## Reader and machine contracts

Machine-readable manifests outrank prose for traversal, inventory, availability, and terminal state. Contributions must not create a prose-only bypass. Readers must not need to recursively ingest the repository or run validators, generators, scripts, tests, or package managers merely to read it.

Keep repository/navigation, assessment, evaluator, implementation, Runtime Validation, and production-qualification states distinct. Each operational transition needs separate, explicit authorization. Preserve the repository as read-only knowledge: examples may explain agent systems, but bare reading must never execute or create them.

## Safety and review

Use synthetic examples and placeholders; never contribute secrets, credentials, private endpoints, personal data, or account identifiers. Follow `SECURITY.md` for private reporting. Keep diagnostics secret-safe.

Before proposing a change, review affected links, terminology, claim classifications, and conflicts with governing machine data using non-live methods. Do not install dependencies or execute validators unless that exact action is authorized. English is the repository language.

By contributing, you agree that attribution must follow `ATTRIBUTION.md` and that published artifacts must preserve applicable licenses and source notices.
